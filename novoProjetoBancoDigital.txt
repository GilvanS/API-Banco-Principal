Novo Planejamento por Tasks para Issues no GitHub (Simplificado e Otimizado)
Este planejamento é a versão mais enxuta e focada, ideal para a sua API de aquisição e geração de massa, mantendo a autenticação simplificada.
Milestone: API de Aquisição Simplificada (NuvemBank)
1. Configuração e Autenticação Simplificada
issue Remover Módulo de Administração:
Excluir todas as rotas e lógicas relacionadas à role: admin.
Remover o role do modelo UsuarioConta ou padronizá-lo para um valor único (e.g., cliente).
issue Remover Módulo de Dispositivos:
Excluir o modelo Device e quaisquer referências a ele.
issue Configurar Geração de Token Inicial Simplificada:
Manter o endpoint POST /auth/login.
Garantir que o token JWT gerado tenha validade de 30 minutos (ajustar a configuração do JWT no backend).
Remover a lógica de forgot-password e reset-password (se não for essencial para a massa).
issue Padronizar Rotas para /api/v1/:
Mover todas as rotas principais para o prefixo /api/v1/ para indicar versão e consistência.
Ex: /clientes -> /api/v1/clientes, /transacoes -> /api/v1/transacoes.
2. Módulo de Clientes e Contas (Aquisição)
issue Endpoint: Criar Novo Cliente e Conta (POST /api/v1/clientes):
Este endpoint será o principal para aquisição de novos clientes e geração de massa.
Ele deve criar um UsuarioConta (com saldo inicial 0, ou um valor configurável para massa) e um Cartao de débito automaticamente.
Remover o campo tipoConta se todas as contas forem corrente por padrão para simplificar.
Garantir que os campos cpf e email sejam únicos.
issue Endpoint: Obter Detalhes da Conta do Usuário Autenticado (GET /api/v1/account/me):
Permitir ao usuário autenticado obter todos os detalhes de sua UsuarioConta (nomeCompleto, cpf, agencia, numeroConta, saldo, etc.).
Este endpoint é crucial para validar a massa criada.
issue Endpoint: Atualizar Dados do Perfil (PATCH /api/v1/users/me/profile):
Permitir ao usuário autenticado atualizar seus dados básicos (nomeCompleto, email, telefone, endereco).
Útil para simular atualizações de dados na massa.
3. Módulo de Cartões
issue Endpoint: Solicitar Cartão de Crédito (POST /api/v1/cards/credit-request):
Permitir ao usuário autenticado solicitar um cartão de crédito.
Usar o usuarioId do token JWT para associar o cartão.
Ajustar a lógica para atribuir um limite padrão para testes.
issue Endpoint: Listar Meus Cartões (GET /api/v1/cards):
Permitir ao usuário autenticado listar todos os seus cartões (débito e crédito).
issue Endpoints: Gerenciamento de Cartão (PIN, Bloqueio/Desbloqueio):
Manter PATCH /api/v1/cards/{id}/pin, PATCH /api/v1/cards/{id}/block, PATCH /api/v1/cards/{id}/unblock.
Esses são úteis para testar cenários de segurança e funcionalidade de cartão.
4. Módulo de Transações Financeiras (Geração de Massa)
issue Endpoint: Depósito (POST /api/v1/transactions/deposit):
Permitir depósitos para simular entradas de dinheiro.
issue Endpoint: Transferência (POST /api/v1/transactions/transfer):
Permitir transferências entre contas (agência/conta) para simular movimentação entre usuários da massa.
issue Endpoint: Compra no Crédito (POST /api/v1/transactions/credit-purchase):
Simular compras no cartão de crédito, atualizando o creditoUtilizado.
issue Endpoint: Pagar Fatura (POST /api/v1/transactions/pay-bill):
Simular o pagamento da fatura do cartão de crédito.
issue Endpoint: Obter Extrato da Conta (GET /api/v1/account/statement):
Com os filtros de data e tipo de transação, este é essencial para validar as movimentações da massa gerada.
