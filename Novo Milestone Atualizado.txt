Prompt Detalhado para a Equipe de Desenvolvimento
Título: Refatoração e Simplificação da API para Foco em Aquisição (Projeto NuvemBank)
Objetivo Principal:
Transformar a API existente, que é completa e complexa, em uma versão enxuta, rápida e focada, cujo principal objetivo é a aquisição de novos clientes e a geração de massa de dados para testes. Devemos remover funcionalidades que não servem a este propósito (como painel de admin e gerenciamento de dispositivos) e otimizar a experiência do desenvolvedor que irá consumi-la.
Diretrizes Gerais:
Simplificação Radical: Tudo que não for essencial para o fluxo de criar um cliente -> logar -> movimentar a conta -> consultar dados deve ser removido.
Foco no Usuário Autenticado: A API deve operar no contexto do usuário logado via token JWT. Endpoints não devem mais receber userId ou clienteId como parâmetro; essa informação deve ser extraída do token de autenticação no backend.
Padronização e Versionamento: Todas as rotas da API devem ser padronizadas sob o prefixo /api/v1/ para garantir consistência e facilitar futuras versões.
Clareza nos Modelos (Schemas): Os modelos de dados devem conter apenas os campos necessários para o escopo definido.
Escopo Detalhado da Refatoração:
Módulos a Serem Removidos:
Administração: Remover completamente todas as rotas /admin, a tag Administração, o schema RelatorioResponse e o campo role dos modelos de usuário.
Dispositivos: Remover o schema Device, a tag Dispositivos e qualquer referência a dispositivos no schema UsuarioConta.
Autenticação:
Manter o endpoint POST /api/v1/auth/login.
Ajustar a validade do token JWT para 30 minutos.
Remover os endpoints de recuperação de senha (/auth/forgot-password e /auth/reset-password).
Fluxo de Aquisição e Conta:
O endpoint principal será POST /api/v1/clientes para criar um novo usuário e sua conta. Simplificar o requestBody para conter apenas o essencial (nomeCompleto, cpf, senha, email).
Substituir todos os endpoints que usam {id} (como /clientes/{id} e /clientes/{id}/saldo) por endpoints que operam no usuário autenticado:
GET /api/v1/account/me (para detalhes da conta)
GET /api/v1/account/balance (para saldo)
GET /api/v1/account/statement (para extrato)
Cartões e Transações:
Refatorar todos os endpoints de cartões (/cards) e transações (/transactions) para não dependerem de usuarioId no corpo ou na URL. A lógica deve sempre usar o ID do usuário presente no token JWT.
Requisitos Não-Funcionais:
Testes: Todos os testes existentes devem ser atualizados para refletir as novas rotas e lógicas. Novos testes devem ser criados para validar o fluxo simplificado.
Qualidade de Código: Aproveitar a refatoração para corrigir os bugs de tipagem e referências já mapeados (ex: req.user vs req.usuario).
Documentação: O README.md e o arquivo Swagger/OpenAPI devem ser atualizados para refletir 100% a nova estrutura da API.
